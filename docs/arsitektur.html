Arsitektur FEAR

Aplikasi work order dan kunjungan lapangan engineer. Frontend dibuild jadi file statis, backend PHP murni, database MySQL. Di server cukup PHP dan MySQL, jadi bisa jalan di shared hosting cPanel biasa tanpa Node.js.

SvelteKit 3 · Svelte 5 Tailwind CSS 4 TypeScript 6 · Vite 8 PHP 8.1+ tanpa framework MySQL 5.7+ / MariaDB 10.3+ Apache / LiteSpeed

Gambaran sistem

Semua request masuk lewat .htaccess. Path /api/* dan /files/* diteruskan ke PHP, path lain dijawab dengan index.html (SPA).

Frontend Backend PHP Database Server / file

Alur request

Halaman dan API memakai path yang sama. Kontraknya sengaja dibuat mirip load dan form action bawaan SvelteKit.

Buka halaman · GET /api/<path>

  1. User membuka misalnya /work-orders/12. .htaccess menjawab dengan index.html.
  2. +page.ts memanggil GET /api/work-orders/12 beserta cookie fear_session.
  3. router.php mencocokkan route, auth.php memeriksa sesi dan role.
  4. Route di work_orders.php menjalankan query lewat PDO lalu mengirim JSON.
  5. Svelte merender data. Kalau error, +error.svelte yang tampil; kalau belum login, user diarahkan ke /login.

Kirim form · POST /api/<path>?/<aksi>

  1. enhance.ts mengirim form dengan header X-Fear-Request: 1.
  2. router.php menolak request tanpa header itu atau dengan Origin berbeda (CSRF).
  3. form.php memvalidasi input, file foto disimpan ke storage/uploads.
  4. Hasilnya {type: success | failure | redirect | error}.
  5. Frontend menampilkan pesan error per field atau pindah halaman sesuai type.

Model data

Panah mengarah dari tabel anak ke tabel induk (foreign key). work_orders jadi pusat: lokasi, jenis kegiatan, tim yang ditugaskan, dan catatan kunjungan semuanya terhubung ke sana.
